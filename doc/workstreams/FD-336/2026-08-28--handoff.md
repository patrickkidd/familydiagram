## Binding design decisions

### Architecture (the ticket's core)
- **One Scene, one Session, one save path.** The embedded views operate on
  Pro's already-open Scene and Diagram; `DiagramSaver` is the single writer for
  both apps. Personal's JSON save path is retired; format stays pickle.
- **`PersonalAppController` decomposed** into components that take a Session and
  never own one. Never pass a bound method of the parent into a child — it
  makes a reference cycle that aborts gc teardown.
- **The coach is server-cases-only.** It reads the persisted server row, so a
  local `.fd` has no row and no discussions. Local-file support is deferred
  (R-0002 area; ticket scope line).
- **Beta-only.** `ALPHABETA` in `version.py` is the one canonical flag (`""` =
  release). All four entry points are gated together: drawer tab, toolbar
  button, View menu item, and Ctrl+4. A hidden `QAction` still fires its
  shortcut, so the action is **disabled** as well as hidden.
- **One order everywhere** (R-0059): drawer tabs, toolbar buttons and View menu
  all follow the Ctrl+1..5 numbering — Diagram, Timeline, Triangles, Chat,
  Settings.

### Things that bit us, and the rule each left behind
- **Never hide a `TabButton` to gate it.** A hidden one still takes its turn in
  the bar's layout and its index. The bar is now built from a list of the tabs
  the build offers; each entry names the stack page it shows, so order and
  membership change without touching pages.
- **Personal QML must not assume an ApplicationWindow.** Its popups parented to
  `Overlay.overlay`, which is null inside Pro's `QQuickWidget`. Each view
  resolves it once on its root and falls back to itself.
- **Qt 5.15.2 wheel bug.** `QQuickWidget::wheelEvent` forwards to its internal
  `QQuickWindow` without a window on the event; delivery then calls
  `QWindow::mapToGlobal` on null and segfaults. Every crash Patrick hit was
  this. `QmlWidgetHelper` filters wheel events and scrolls the Flickable itself:
  trackpad follows macOS's own momentum phase, a discrete wheel is handed to
  `flick()` for Qt's inertia. **Do not remove this before the Qt 6 port.**
- **A batch add suppresses per-item scene signals and never replays them.** The
  timeline missed committed extractions and ordinary loads until it resynced on
  `finishedBatchAddingRemovingItems`. Assume this class of bug for anything
  listening to per-item scene signals.
- **The chat must never render blank.** Three separate causes each surfaced as
  an empty tab. The reason text now always resolves to something, and a test
  fails if the tab is ever inactive and empty.

### Harness decisions
- **The sandbox keeps one data directory per ticket.** A fresh temp dir per
  launch meant the app reopened a `.fd` from a dead sandbox — a case with no
  server identity. It also meant a backend restart discarded Patrick's test
  data, which happened to him (R-0045).
- **`bin/sandbox apps FD-NNN`** relaunches the apps against the running backend,
  data untouched. `up`/`down`/`reseed` destroy data — only on his say-so.
- Visible launches are real macOS apps: `QT_QPA_PLATFORMTHEME=offscreen` and
  `QT_QUICK_BACKEND=software` are headless-tier only, and the app gets its own
  process group, not its own session.
- **Crashes are captured**: the app writes straight to its log file and
  `faulthandler` is enabled, so a segfault leaves a stack. `--debugger` runs it
  under lldb for the C++ frame; `--bridge` exposes the test bridge for live
  introspection.
- **The bridge can inspect QActions** (visible, enabled, text, shortcut). Menu
  items and shortcuts were invisible to the harness before, which is why the
  beta gate went unverified on those two entry points through five of Patrick's
  eyeball checks.

### Test-harness decisions
- **Build state and licence are independent, markable and parametrizable.**
  `@pytest.mark.beta` sets both; `betaBuild` and `licenseProduct` can be
  parametrized indirectly for any combination.
- **Why that matters:** a beta build honours beta licences and strips every
  other one, so a beta-marked test with a professional licence launches with no
  active features and blocks on the "Beta License Required" modal. That was the
  freeze behind `test_show_chat`'s xfail — Patrick diagnosed it. Launch modals
  are now recorded, not shown, so the combination is assertable.
- **Never name a test file after a ticket** — the guard enforces it.
- **Validate UI with screenshots and harness introspection**, not property
  queries alone (R-0056).

## The plan — agreed 2026-08-28

Patrick's framing (R-0060): this need not be perfect, but the **load-bearing
plumbing must be finished here**. He will find remaining bugs himself across the
next units before users see it. Chat UX polish, coach behaviour, extraction
quality and prompt feel are explicitly *not* load-bearing.

**Owed before merge:**

1. **Make server-identity binding structural.** `onServerFileClicked` is the
   only path that binds a case's server identity — the coach,
   `setServerDiagram`, and the id allocator. Any other open path silently loses
   all three, and a save then writes locally instead of to the server. The
   launch race is fixed (`openLastFile` waits for the server index) but the
   structure is still a trapdoor. **Data integrity, not UX.**
2. **Prove the committed data shape round-trips.** The writer decides what is
   persisted forever. `confidence` no longer leaks into the scene, but a
   committed pair bond still lacks the child items (`detailsText`,
   `separationIndicator`) an app-created marriage has. Unresolved whether that
   round-trips through save/load cleanly.
3. **Write the Pro→Personal journey** (R-0061, currently GAP). An edit made in
   Pro must appear in the embedded Personal views. Its failure mode is silent —
   two views quietly disagreeing — and it is the ticket's core promise. One
   instance of this class is fixed (the batch-signal timeline bug); the general
   case is unproven.

**Raised, not insisted on:** two `EventForm` instances exist when embedded
(Pro's drawer form and `ProPersonal`'s), both bound to the same Scene. Nothing
says which the user gets or that they agree. Cheap to unify now, awkward once
later units build on it.

**Also open, Patrick's call:**
- Whether the newest-Opus chat model ships with this PR or gets a coach-eval
  baseline first. It also unmasked a pre-existing bug where Premium never used
  the Opus-tuned prompt, so coach style changes.
- Whether `--llm real` stays opt-in (it bills his key per turn).
- Two AC lines he agreed belong on the ticket (Pro→Personal; event-form
  coherence). **Nothing has been written to Jira** — never create or edit a
  ticket without asking (R-0053).
- The server-side disk cache may be removable now that offline sync is gone —
  he raised it, I sized it as risky: `FDDocument` is path-based with no
  bytes-in/bytes-out API, and attached files live in the package. Not this
  ticket.
- Qt 6 port is coming (5.15.2 is buggy and the GitHub runners will drop it).
